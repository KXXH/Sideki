# 对话权限与自动审批

## 模式和存储

`PermissionMode` 为 `ask`（请求批准）、`auto`（自动审批）、`allow`（全部允许）。输入框修改当前 `ChatSession.permissionMode`；设置页仅修改 `ApiConfig.defaultPermissionMode`，新会话创建时复制默认值。已有会话缺少字段时按旧 permissive/yolo 配置推导，不读取后来修改的新对话默认值。网络配置独立，全部允许不自动开启联网。

## 执行链路

`createAgent` 的 SDK `toolApproval` 回调覆盖内置工具和动态 MCP；参数完整后、`execute` 前进入 `ApprovalService`。runtime 和 panel 回退共用该服务。后台 `ApprovalManager` 登记会话、turn、工具名、参数、目标页和版本，只读工具（当前为 getPageContent、wait、useSkill）及全部允许可以直接获得执行凭证。请求批准沿用原普通确认；其他 auto 调用运行独立 reviewer。

`approval:prepare` 创建请求，`approval:bash` 调查，`approval:complete` 接收二元判定，`approval:cancel` 撤销，`approval:finish` 清理。获批凭证通过桥接元数据传递，不是模型参数。后台核对完整参数、目标与版本并单次领取；Bash 在会话锁内绑定执行授权，页面命令、Chrome 命令、MCP 子命令继承同一次授权，不重复启动 reviewer。独立 debugger/CSP 授权不由普通凭证扩大。

停止任务撤销审批及执行范围，Bash 取消信号中止后续命令；已发生的外部副作用不回滚。模式切换取消旧待审批请求并按新模式重新判断，执行中调用继续使用原模式。迟到响应不能恢复已撤销授权。SW 重启丢失的凭证不能继续使用。

## 审批上下文与模型

固定窗口为最近 5 条用户消息、最近一个已完成用户 turn 和当前 turn 的助手公开正文、最近 10 次工具调用参数及状态/错误（不含返回载荷）。保留角色与消息来源，不以模型摘要、助手声称或工具描述代替用户授权。当前完整参数单独提供，超过 24000 字符直接拒绝；总上下文预算 48000 字符，历史条目按固定规则裁剪并标记。内置工具的展示 description 被剥离，MCP 业务参数不按同名字段剥离。

审批器使用主模型的 provider/model、独立 low 推理配置、最多 5 个模型步骤和 30 秒总预算。调查使用只读 Bash，最终必须单独调用 `submitApproval({decision: 'allow' | 'deny', reason})`，该工具没有 execute，收到合法调用后立即终止，不再请求总结。最后一个模型步骤通过 tool_choice 强制调用此工具，本地同时禁止继续 Bash 调查。判定不再依赖 `Output.object` / response_format，不解析自然语言、JSON 正文或 Bash stdout。缺失、无效、重复或混合工具提交属于审批异常，保持不执行，并与模型风险拒绝区别显示。错误、超时、证据不足由主 agent 决定后续行动，不弹人工确认或静默更换模型。调用之间不继承旧判定历史。审批用量、耗时与主执行分开统计。

审批系统指令、工具描述与 schema 固定为模块级定义；系统提示明确最多 5 轮模型调用、总共 5 次工具调用（包含最终判定），每轮最多调用一个工具，最多调查 4 次 Bash，第 5 轮仅提交判定；证据足够时提前结束，预算不足时拒绝并说明缺失证据。这是提示词层面的工具次数约束，运行时仍以 5 个模型步骤作为硬上限。所有请求和模型步骤都以 `bash`、`submitApproval` 的固定顺序发送完整工具列表，最后一步也不删减。变化的审批材料放在独立 user 消息中，内部依次排列用户消息、助手公开正文、近期操作、环境与当前完整调用；待审调用放在末尾。只读调查结果在本次运行中追加，不回写固定指令。此结构提供可复用前缀，不承诺服务商必然命中缓存；不额外发起预热请求，也不复用历史判定。

审批模型每次响应的用量在 provider 中间件收到响应后、SDK 校验判定协议前采集，归入父会话并标记 `source: 'approval'`。Dev 审批汇总和逐步用量使用同一份采集结果，保留格式异常、取消或超时前已收到的用量；成功返回的总用量不重复累加。服务商未返回 usage 的部分无法补算，缺失值不冒充精确零。审批次数包括实际启动的失败调查，普通规则放行不增加模型审批次数。全局统计支持主会话与自动审批分离查看，详见 [前端与会话同步](frontend.md)。

## 只读调查

`review-shell.ts` 使用独立 Bash 和只读 `IFileSystem` facade。对主 VFS 提供按需读取视图，不复制全部文件；任何文件修改接口（包括元数据、链接、目录操作）均拒绝。修改版本或实例变化使旧视图失效。单文件读取 512 KiB、累计读取 2 MiB、单次执行 5 秒、输出 12000 字符，保留通用查询与管道；网络、Python、任意 JS 和写入型自定义命令不注册。

页面仅通过固定的 ISOLATED 读取函数访问绑定目标，校验 URL、timeOrigin 和可用的 documentId；不安装 resolver 或修改页面全局变量。支持 `page-content [--html]`、`dom [--root=CSS]`、`element-info CSS`。审批前后文件或页面变化则拒绝旧判定。

## 验证范围

Dev 面板的「审批 Agent」入口提供独立 reviewer inspector。选择一次调用后，分别查看固定指令、初始审批上下文、工具 schema，以及 SDK 实际每轮输入、公开输出、工具调用和工具返回。每轮包含模型/provider、时间和用量；推理项与 provider 私有数据只保留省略标记，不展开。最终输出区区分模型判定和后台应用的判定。人工路径、全部允许和读取规则放行明确标记为未启动审批 Agent，不能伪造模型轨迹。

Inspector 通过当前会话的按需请求读取，不把完整上下文塞入高频镜像 patch。仅在打开时每 2 秒刷新，可复制本次记录、清空记录；记录存在宿主内存，最多 30 条、总量约 1 Mi 字符，超限裁剪旧记录或明确标记截断，宿主重启后清空。API 凭证和执行 permit 不进入记录。

「仅测试审批 Agent」沿用当前会话授权上下文和当前模型，对输入的完整 Bash 调用强制运行自动审批；不改变会话权限，不执行待测命令，始终撤销测试生成的执行凭证。该测试会产生真实模型调用，记录明确标记为 diagnostic。Dev 文件会话选择与当前 Chat 会话不一致时，要求先在 Chat 打开所选会话，避免展示其他会话的上下文。

自动化测试覆盖固定上下文窗口、二元判定回传、取消与模式变更、单次凭证领取、跨会话隔离、只读写入旁路、页面来源/版本和 UI 状态。真实模型延迟及不同 provider 的结构化输出兼容性、Chrome 中的页面交互观感需要运行扩展实测；失败时执行保持拒绝。
