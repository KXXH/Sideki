# 后台内核与多会话 — 手动验收清单

本清单对应当前 offscreen 默认宿主与 panel 回退路径。复选框均表示待人工执行，不代表已有真机验收结论。自动化测试覆盖状态与协议，但无法替代 Chrome 的 offscreen、port、调试器和页面焦点行为验证。

## 前置

1. `npm run build`，在 Chrome 加载固定目录的 `dist/`；更新已有安装时直接重新加载，保留原加载目录。
2. 设置 → 开发者 → 兼容性与故障排查，确认「后台内核（Offscreen）」开启（缺省及新配置均使用 offscreen）。
3. `chrome://extensions` → Sideki → 检查 offscreen 视图；在其控制台确认 `[offscreen] kernel host ready (multiplexed)`。该日志属于 offscreen 页面，不是 SW。
4. 准备已连接的模型；多会话隔离测试使用两个普通网页和两个 Chrome 窗口。

## A. 宿主开关与连接恢复

- [ ] 默认开启时重开面板，会话和消息由后台快照恢复。
- [ ] 空闲时关闭开关，切到 panel 宿主，已保存的会话可正常读取和继续；再开启时恢复 offscreen 镜像。
- [ ] 开关切换不清空设置、消息、压缩历史或 VFS。测试前先让当前 turn 结束；不把切换宿主视为流式任务的无损迁移。
- [ ] 在后台握手尚未完成时立即发送：正常冷启动应等待绑定就绪后发送；后台持续不可用时，约 5s 后提示失败，输入与附件保留。
- [ ] 面板反复开关 5 次，每次状态一致，无重复消息；断线后会重新握手取快照，补丁 rev 缺口能触发 resync。
- [ ] 上传过程中切换会话：发送被取消且输入、附件仍在，文件与消息不会进入错误的会话。

## B. 面板关闭后继续运行

- [ ] offscreen 模式发送长任务后立即关闭面板，后台继续执行；重开时显示正在进行或已完成的回复。
- [ ] turn 完成后会话已持久化，重开面板可见完整回复。
- [ ] 无可见面板观看该会话时，按完成通知设置收到通知；点击通知回到对应窗口、模式与会话。
- [ ] 正在观看该会话时不重复通知；重新看到会话后清理其旧通知。

## C. 多窗口与会话多路复用

- [ ] 两窗口绑定同一会话时，消息和队列同步；同一 ID 的重试命令不重复执行。
- [ ] 两窗口绑定不同会话时，各自发送、停止和队列操作互不改写另一会话。
- [ ] 两个 turn 同时执行且目标 tab 不同，工具命中各自 tab 和 VFS。
- [ ] 会话 A 已占用某 tab 时，会话 B 对该 tab 的页面工具得到占用错误，A 不受干扰。
- [ ] A 运行期间用户切换 tab，A 的工具仍留在自己 turn 的 tab 栈；A 打开 `_blank` 时正确跟随，B 的目标不被牵动。
- [ ] 队列连续执行期间用户切 tab，下一条排队项仍沿用原操作栈；队列排空或错误结束后释放。
- [ ] 保温窗口内切回会话，无需重新冷加载。释放后等待超过 30s，并让空闲 runtime 数超过默认上限 3，再验证逐出落盘与冷加载恢复。
- [ ] 流式中关闭窗口，繁忙 runtime 保留至任务结束；之后才按宽限与空闲容量判断逐出。
- [ ] 删除被另一窗口绑定的会话，对方重新绑定幸存会话并收到快照；被删会话不会因延迟保存重新出现。
- [ ] 窗口内 tab↔session 记忆正常：tab1 使用甲、tab2 使用乙，切回时恢复对应会话，繁忙和锁定条件下不误切。

## D. 中断与 checkpoint 恢复

- [ ] 流式中重新加载扩展后，会话恢复到最近成功保存的 checkpoint。
- [ ] 若最后一条为 assistant，恢复时携带 `interrupted` 元数据；状态为 ready，可以继续发消息。
- [ ] 未完成的工具调用在下一次出站时转换为错误结果，模型 API 不因缺少 tool result 拒绝请求。

流式 checkpoint 由内核状态通知触发，间隔条件为超过 5s；存储异步且可能失败，因此验收应核对“最近成功保存的内容”，不能承诺所有崩溃下最多损失 5s。

## E. 无响应 offscreen 自愈

- [ ] 用 offscreen DevTools 断点暂停页面后重开面板，4s 握手超时会断开重连；SW 在启动宽限以外 ping 两次无响应后重建文档。
- [ ] 健康文档直接响应 ping，不因普通重连被重复创建；刚创建的文档有 10s 启动宽限。
- [ ] 多窗口同时打开面板，不发生交错 createDocument/closeDocument 的重建循环。
- [ ] SW 中的 `[SW] offscreen document unresponsive, rebuilding` 仅在实际无响应场景出现。

## F. 全链路功能

- [ ] Stop 中断流式回复；错误和中止后的 tab 锁、页面工作指示器按预期释放。
- [ ] preparing、dispatching、streaming 或 compacting 时发送会正确排队；完成后按 FIFO 继续。
- [ ] 队列删除与取回编辑、新建/切换/删除/重命名会话正常。
- [ ] 首条回复后生成标题；重新生成保留附件、skill 和页面来源，不把定时唤醒误当普通用户消息重发。
- [ ] `labAutoCompress` 开启时，旧工具结果在 turn 边界归档；达到 80% 且超过 30s 冷却时压缩历史，UI 可展开查看原始消息。
- [ ] bash、click、screenshot 和 MCP 正常；Pro 与 Chat 工具能力及授权各符合当前模式。
- [ ] visualize 画布正确加载、调整高度并跟随主题；刷新会话仍能读取其 VFS 快照。
- [ ] 同一 HTML 快照在画布和新标签页中运行相同的交互与主题变量；完整文档和片段均按共享能力契约处理，扩展 API、VFS 相对依赖、嵌套文档及外部导航不能因换入口获得额外能力。
- [ ] 画布的 `network` 参数仍控制自身模式；工具 `previewPath` 和 `VizFrame` 的新标签页 URL 均显式携带同一 `network=1|0`，相同档位的两个入口符合一致的 sandbox/CSP 能力。
- [ ] 新标签页仅在 `network=1` 时联网；`network=0`、缺失、空值或无效值均离线。修改 Query 可独立切换模式，旧 `.meta.json` 即使冲突或损坏也不读取、不报相关错误且不被删除。
- [ ] 未经 `visualize` 的独立 HTML 可直接由 `[查看](/viz/report.html?network=1)` 打开联网预览；侧栏关闭后仍独立运行。
- [ ] 同时打开两个不同会话的同名 HTML 与图片，内容各自正确，无串会话；图片和下载原文件的二进制字节保持完整。
- [ ] 模拟文件读取无响应或 sandbox 不握手，分别在读取/渲染预算内显示错误；重试后旧 iframe 的错误或 rendered 消息不改变新预览状态。
- [ ] 定时唤醒与页面监听在面板关闭后继续由后台执行；暂停、恢复、取消及唤醒消息正确。
- [ ] Dev 面板 Session 检查器按需读取当前 runtime 的 craton / orogen，出站预览与实际消息处理一致。

## G. UI 阻塞点与无面板授权

- [ ] Chat strict 模式的操作确认及 debugger 授权仍在目标窗口的面板弹出；picker 回填正常。这些消息经 SW↔面板传递，不通过内核镜像命令。
- [ ] 面板全关时需授权的工具保持挂起；重开面板后可以授权继续。源码重试间隔为 3s，最长约 5 分钟；明确拒绝应立即失败，不等待重试。
- [ ] 超时或 SW 被终止时操作未获授权，不出现自动放行。

## H. 存储与 bundle

- [ ] 使用旧 `sidekick_sessions` 数据启动后，迁移页显示进度，完成后确认进入；旧会话变为索引与独立正文，消息完整。
- [ ] 迁移中重载或模拟失败后可重试，不需要清空数据。
- [ ] 面板、options、阅读器、offscreen 和 background 均无模块加载异常；SW 无 DOM/window 依赖污染。
- [ ] 卸载前先导出备份；此清单中的重新加载不应被替换为卸载重装。

## 已知边界

- 面板关闭后可以继续运行已有 turn，但 bridge 主动输入仍依赖面板接收并注入；不能把“回传在后台工作”等同于“所有 bridge 输入均已 headless 化”。
- offscreen document 和浏览器进程仍可能被终止；恢复以成功保存的会话为准，不是服务端任务托管。
- 无面板 consent 等待仍依赖 SW 存活；SW 强杀时调用会失败，不能认为挂起的请求一定可恢复。
- 手动关闭后台内核是兼容性回退，不是运行中任务的热迁移承诺。
