# Sideki

![Sideki — 浏览器里的通用智能 Agent](docs/assets/sideki-teaser.png)

Sideki 是一个运行在 Chrome 侧面板中的通用智能 Agent。

告诉它你想完成什么，它会结合当前页面理解目标、规划步骤，并使用工具推进任务。从阅读资料、整理信息，到操作网页、构造交互界面，Sideki 就在你工作的地方，和你一起把事情做完。

## 给 Agent 工具，也给它空间

我们相信，通用 Agent 应当有空间自主解决问题。

因此，Sideki 选择提供 Bash、虚拟文件系统、基础的 JavaScript 执行和浏览器操作能力，让 Agent 根据目标决定如何组合使用。面对新的需求，它可以编写脚本、处理数据、操作页面，形成适合当前任务的方法，无需为每一种任务提前准备一个专用工具。

我们也希望 Sideki 能与你共同成长。通过记忆保留你的偏好和工作背景，通过技能沉淀可复用的方法。你可以和它一起，把一次任务中有效的做法整理成技能，让积累的经验成为下一次协作的起点。

## 浏览器，就是 Sideki 的世界

我们刻意将 Sideki 的执行环境与你的本地环境分开。

Sideki 使用的 Bash 和文件系统都运行在浏览器中的虚拟环境里。每个新会话拥有独立的文件工作空间，记忆和技能则让有价值的经验可以跨会话延续。它可以自由地编写脚本、处理文件，而无需获得你电脑上的终端权限。

这样的设计让虚拟文件系统中的一次错误操作，不会直接删除你电脑上的文件。

浏览器中的操作仍然可以影响现实世界，例如提交表单、发送消息或修改网站中的数据。Sideki 提供操作权限控制；处理敏感页面和重要操作时，仍需要你保持关注。

## 让界面随对话生长

我们认为，Agent 应当能够自主构造交互界面，让表达超越纯文本和 Markdown。

在适合的时候，Sideki 可以在对话中生成一张图表、一个可以调整参数的计算器、一段可探索的 3D 演示，甚至一局纸牌游戏。界面由当前的问题和任务决定，让你通过观察、操作和尝试，继续理解与探索。

我们希望这些界面像标题、表格和图片一样，自然地出现在会话中，成为交流的一部分。

## 和你共用浏览器，也有自己的工作节奏

交代任务之后，你可以继续自己的工作。

Sideki 的后台内核让任务可以在侧面板关闭后继续执行，并在完成时通知你。它也可以定时执行任务，或监听页面变化，在条件满足后接着处理。等待导出、检查进度，不必一直守在对话前。

任务执行期间，Sideki 会维护自己的标签页栈，记住正在操作的页面，以及从哪里打开了新页面。你切换标签页时，它的操作目标不会随之改变；多个会话之间也会协调页面的使用，减少任务互相干扰。

页面上的拟真指针、操作轨迹和工作提示，让你能看见它正在哪里、做什么。我们希望自主执行的过程仍然清晰可感知，让你可以在需要时回来查看、补充要求或停止任务。

## 为持续工作而设计

多步任务会积累越来越多的资料。Sideki 可以把较早的工具结果归档到文件，需要时再查阅，并通过历史压缩管理上下文空间。

缓存友好也是 Sideki 的基础设计之一。我们尽量复用稳定的上下文，减少多轮对话和连续执行中的重复输入开销。实际缓存命中与费用取决于所连接的模型服务。

## 快速开始

1. 前往 [Releases](https://github.com/KXXH/Sideki/releases/latest)，下载 `Sideki-v版本号.zip`。
2. 解压到一个固定目录。
3. 打开 `chrome://extensions/`，启用右上角的**开发者模式**。
4. 点击**加载已解压的扩展程序**，选择包含 `manifest.json` 的目录。
5. 点击 Sideki 扩展图标，按引导连接模型。

打开一个网页，告诉 Sideki 你想做什么，就可以开始。例如：

- “帮我比较这几个页面里的方案，整理出它们的差异。”
- “把这些数据做成可以调整参数的交互图表。”
- “等这个页面的导出完成后，提醒我。”
- “把刚才的处理方法整理成一个技能，下次继续用。”

更新前建议在设置中导出完整备份。将新版文件更新到原加载目录，再在扩展管理页点击**重新加载**，沿用现有数据和配置。

## 连接模型与工具

Sideki 支持连接不同的模型服务，使用你自己的 API Key。

我们推荐从 **DeepSeek 官方 API** 开始。Sideki 对稳定上下文的复用，可以配合其[缓存计费](https://api-docs.deepseek.com/quick_start/pricing/)降低连续对话和多步任务的输入成本。你也可以根据任务，在模型能力、响应速度和成本之间做自己的选择。

Sideki 支持通过 MCP 连接外部工具和服务。如需网络搜索，可以在设置的 MCP 配置中添加 [Exa Search MCP](https://exa.ai/mcp)：

```text
https://mcp.exa.ai/mcp
```

对于开发与调试任务，Pro 模式提供更深入的页面、网络和运行状态检查能力。

## 数据与隐私

对话、配置和附件默认保存在浏览器本地，支持导入与导出。

Sideki 不依赖自建的云端中转服务。模型调用与 MCP 请求由浏览器直接发送到你配置的服务，不经过 Sideki 服务器中转。执行任务所需的对话、页面和附件内容，会按需发送给对应服务。

模型调用费用由对应服务商收取，数据处理方式也取决于你选择的服务。

## 使用边界

- `chrome://` 等浏览器内部页面受到 Chrome 的访问限制。
- 会话的虚拟文件空间彼此独立，网站登录状态仍由浏览器共享。
- HTML 画布默认离线运行，可以按需显式启用联网。
- 标签页栈用于保持任务的操作目标；部分网页操作仍可能打开前台页面，任务不保证全程不打扰焦点。
- 后台执行与定时任务需要浏览器运行、设备处于唤醒状态。浏览器重启后，需要重新确认任务绑定并恢复。

## 从源码开发

需要 Node.js 24。

```bash
git clone https://github.com/KXXH/Sideki.git
cd Sideki
npm ci
npm run dev
```

开发服务默认使用端口 `5174`。在 Chrome 中加载 `dist-dev/`，并保持开发服务运行。

| 命令 | 用途 |
|---|---|
| `npm run dev` | 开发模式，输出到 `dist-dev/` |
| `npm run build` | 生产构建，输出到 `dist/` |
| `npm test` | 自动化测试 |
| `npm run lint` | ESLint 检查 |

生产构建的 `dist/` 可以独立加载，无需运行开发服务。

技术架构与模块说明见 [技术文档](docs/README.md)，版本变化见 [更新日志](CHANGELOG.md)。
